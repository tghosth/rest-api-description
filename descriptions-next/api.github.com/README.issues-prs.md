# GitHub Issues & Pull Requests API - Read-Only OpenAPI Schema

This directory contains a trimmed-down version of the GitHub REST API OpenAPI schema that includes **only** issue and pull request related endpoints for reading and searching.

## File: `api.github.com.issues-prs.json`

This file is a subset of the full `api.github.com.json` schema, containing only GET operations related to GitHub Issues and Pull Requests.

### What's Included

The schema includes **30 endpoints** for accessing GitHub Issues and Pull Requests data:

#### Issue Endpoints (16 endpoints)
- **Global Issue Endpoints**: List issues assigned to user, search issues
- **Repository Issue Endpoints**: List/get issues, comments, events, timeline, dependencies, parent/sub-issues

#### Pull Request Endpoints (14 endpoints)
- **Repository Pull Request Endpoints**:
  - `GET /repos/{owner}/{repo}/pulls` - List pull requests
  - `GET /repos/{owner}/{repo}/pulls/{pull_number}` - Get a pull request
  - `GET /repos/{owner}/{repo}/pulls/{pull_number}/commits` - List commits on a pull request
  - `GET /repos/{owner}/{repo}/pulls/{pull_number}/files` - List files changed in a pull request
  - `GET /repos/{owner}/{repo}/pulls/{pull_number}/merge` - Check if a pull request has been merged
  - `GET /repos/{owner}/{repo}/pulls/{pull_number}/reviews` - List reviews on a pull request
  - `GET /repos/{owner}/{repo}/pulls/{pull_number}/reviews/{review_id}` - Get a review
  - `GET /repos/{owner}/{repo}/pulls/{pull_number}/reviews/{review_id}/comments` - List comments for a review
  - `GET /repos/{owner}/{repo}/pulls/{pull_number}/comments` - List review comments on a pull request
  - `GET /repos/{owner}/{repo}/pulls/{pull_number}/requested_reviewers` - List requested reviewers
  - `GET /repos/{owner}/{repo}/pulls/comments` - List review comments in repository
  - `GET /repos/{owner}/{repo}/pulls/comments/{comment_id}` - Get a review comment
  - `GET /repos/{owner}/{repo}/commits/{commit_sha}/pulls` - List pull requests associated with a commit
  - `GET /repos/{owner}/{repo}/branches/{branch}/protection/required_pull_request_reviews` - Get pull request review protection

### What's NOT Included

This schema **excludes**:
- Organization-level issue endpoints
- Issue type management endpoints  
- Repository-wide comment and reaction listings
- Reaction endpoints for issues and comments
- Label listing endpoints
- All endpoints that create, update, or delete issues or pull requests (POST, PATCH, PUT, DELETE methods)

### ChatGPT Action Compatibility

This schema is optimized for use as a ChatGPT action:
- All operationIds use camelCase format (e.g., `issuesList`, `pullsList`, `pullsGet`)
- OperationIds are valid identifiers containing only alphanumeric characters
- No special characters (slashes, hyphens) that might cause issues with tool ID mapping
- All operation descriptions are truncated to 300 characters maximum (ChatGPT action limit)
- All parameter references (`$ref`) have been inlined with explicit `name` fields

### Generation

This schema was generated by:
1. Starting with the issues-only schema (22 endpoints)
2. Adding pull request GET operations (15 endpoints)
3. Removing less commonly used endpoints to meet ChatGPT's 30-operation limit:
   - Organization-level issue endpoints
   - Repository-wide comment/reaction listings
   - Issue label listing endpoints
4. Keeping only GET operations (read-only)
5. Recursively resolving all component references (schemas, parameters, responses, etc.)
6. Converting operationIds to camelCase for tool compatibility (e.g., ChatGPT actions)
7. Truncating descriptions to 300 characters maximum
8. Inlining all parameter references with explicit names
